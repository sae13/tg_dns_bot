# Epic 1 Context: گذاشتن ایمن آخرین پیام

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

کاربر بتواند پیام متنی کوتاه یا بلند را روی صندوقی مجاز بگذارد و مطمئن باشد که اعتبارسنجی، همزمانی، خطای ارائهدهنده و انتشار چندقطعهای هیچ پیام ناقص یا ترکیبی منتشر نمیکنند. این حماسه مسیر کامل ارسال را از راهاندازی امن تا تأیید ثبت فراهم میکند.

## Stories

- Story 1.1: راهاندازی امن ورکر و وبهوک تلگرام
- Story 1.2: پذیرش فرمان ارسال و اعتبارسنجی صندوق
- Story 1.3: ساخت و رفتوبرگشت پیام مدیریتشده
- Story 1.4: قطعهبندی پیام بلند و برنامهٔ انتشار
- Story 1.5: ذخیرهٔ پیام کوتاه روی کلودفلر
- Story 1.6: انتشار امن پیام چندقطعهای
- Story 1.7: ترتیب ارسالهای همزمان و محدودسازی نرخ
- Story 1.8: مدیریت خطا، تلاش مجدد و نتیجهٔ نامعلوم

## Requirements & Constraints

- فرمان ارسال نام کامل صندوق را از آرگومان نخست و متن را از باقی ورودی میگیرد و ورودی ناقص را پیش از اثر جانبی رد میکند.
- نوشتن فقط روی خود دامنهٔ مجاز یا زیردامنهٔ واقعی آن است؛ چند دامنه و ناحیهٔ کلودفلر پشتیبانی میشوند.
- پیام نسخهدار شامل شناسهٔ عددی تلگرام، نام کاربری اختیاری، زمان معیار و متن است؛ زمان در نمایش به وقت ایران تبدیل میشود.
- آخرین ارسال کامل جایگزین پیام قبلی میشود و تاریخچه نگهداری نمیشود.
- قطعهبندی برحسب بایت payload نهایی است و فارسی، شکلک و نویسههای ویژه باید بدون تغییر رفتوبرگشت کنند.
- موفقیت API کلودفلر برای تأیید ارسال کافی است؛ پاسخ کاربر باید هشدار حافظهٔ نهان داشته باشد.
- رازها و متن کامل پیام در گزارش معمول ثبت نمیشوند.
- خطاهای موقت حداکثر سه تلاش با تأخیرهای دو و چهار ثانیه و jitter دارند؛ مهلت فراخوانی پانزده ثانیه و بودجهٔ کل چهلوپنج ثانیه است.
- ارسال عمومی بدون فهرست مجاز کاربر است؛ محدودسازی نرخ اتمی برای فرستنده و صندوق اعمال میشود.
- نسخهٔ نخست روی Cloudflare Workers و بهصورت درخواستمحور است؛ Worker اصلی stateless و هماهنگی توزیعشده در Durable Object است.

## Technical Decisions

- معماری ششضلعی TypeScript است: دامنه مستقل، کاربردهای ارسال و درگاههای بیرونی، Worker webhook و سازگارکنندههای fetch برای تلگرام و کلودفلر.
- تنظیمات از bindings نوعمند و رازها از Secret Store خوانده میشوند؛ webhook با secret token تلگرام محافظت میشود.
- قرارداد انتقال با پیشوند ثابت نسخهٔ نخست و Base64URL بدون padding روی JSON معیار UTF-8 با ترتیب کلیدهای مصوب است.
- رکورد اصلی manifest و نقطهٔ commit است؛ قطعههای شمارهدار تازه پیش از آن نوشته و قطعههای قدیمی پس از آن پاک میشوند.
- فقط سازگارکنندهٔ کلودفلر مالک retry است؛ نتیجهٔ نامعلوم با بازخوانی و تطبیق شناسهٔ پیام reconcile میشود.
- ارسالهای هر صندوق در Durable Object بهصورت FIFO اجرا میشوند؛ dedup update تلگرام و پذیرش نرخ نیز همانجا اتمی است.
- محدودکنندهٔ نرخ در Durable Object پنجرهٔ لغزان و وضعیت پایدار لازم را نگه میدارد.
- پشتهٔ اولیه: TypeScript، Cloudflare Workers، Wrangler، Durable Objects و Vitest؛ همهٔ APIهای بیرونی با fetch فراخوانی میشوند.

## UX & Interaction Patterns

- خطای ورودی باید روشن و همراه نمونهٔ فرمان صحیح باشد.
- تأیید ارسال نام صندوق، زمان ثبت و هشدار احتمال مشاهدهٔ مقدار قبلی در حافظهٔ نهان را نشان میدهد.
- قابلیت غیرفعال پیش از هر فراخوانی بیرونی پاسخ روشن میدهد.

## Cross-Story Dependencies

داستان نخست Worker، webhook امن و قرارداد bindings را ایجاد میکند. داستانهای بعدی بهترتیب اعتبارسنجی ورودی، codec، قطعهبندی، ذخیرهٔ تکقطعه، انتشار چندقطعه، همزمانی و بازیابی خطا را روی همین پایه تکمیل میکنند؛ هیچ داستانی به داستان پس از خود وابسته نیست.
